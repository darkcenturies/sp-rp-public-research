Module: $fastman92limitAdjuster.asi+0xAA110
Problem: The special-actor loader tried to read an empty file-directory entry. In the investigated PSYCHO case, Eagle already registered the actor as ordinary model 48876, while the trainer requested it as a special actor.
Solution: Install or update Valkyrie Crashfix 2.2.2 or later from https://sp-rp.com/#valkyrie-crashfix. Keep one active copy and check its log for the special-actor hooks. # doctor-valkyrie crash rules - Project Eagle
#
# Format is CrashInfo's, so the MixMods community list (CrashList.txt) works
# alongside this file unchanged. Blocks are separated by blank lines.
#
#   Error:    crash address, as printed in the log. Several may be listed.
#   Library:  matches "Last library loaded"
#   File:     matches "Last file loaded"
#   Module:   matches the module the crash address is inside
#   Code:     matches the exception code
#   Problem:  what is wrong          (printed to the player)
#   Solution: what to do about it    (printed to the player)
#
# A rule matches when every key it declares matches, and the rule that matched
# the most keys wins. That is why a rule here with File: + Error: beats the
# community list's entry for the same address - ours knows it is Project Eagle.
#
# Every rule below was derived from crash logs posted in #bugs-problems, and
# the fix in each was confirmed by the person who reported it. Where a fix was
# only partial, the rule says so rather than pretending.

Error: 0x00749B7B
Problem: A script or game function tried to use a model or file that was not loaded or did not exist when it was requested. The last-file line may show unrelated background streaming, so it does not necessarily name the missing model.
Solution: Reproduce the action and identify the model requested by the script, trainer, mission or spawned object immediately beforehand. Make sure that model is registered and loaded before the function uses it. This address can have other causes, so preserve the complete report and compare the file history if loading the expected model does not fix it.

Error: 0x49646550
Problem: The game probably could not retrieve an item, model or texture from the game folder. This address is not fully understood: it has also appeared around old mission script errors, so Doctor cannot honestly name one certain cause yet.
Solution: Preserve the complete report and note the mission or action that immediately preceded the failure. Check that the referenced model and texture files exist and are registered. Also check that ENHI (Enterable Hidden Interiors) was not installed over Project Eagle. In gta_sa.exe Properties, test Run as administrator and set High DPI scaling override to Application. Windows DEP has also been suggested historically, but do not disable system-wide protection for an unconfirmed diagnosis. More reproduced reports are needed to distinguish a missing game asset from a logical script error.

Error: 0x006E3D9C
Problem: The game encountered a problem in an animation or animation group, often during the last action performed, such as entering, leaving or using a vehicle.
Solution: Record the exact action and model involved immediately before the crash and send the complete report to the Project Eagle developers. The relevant animation group may be missing, invalid or incompatible; test without animation-changing scripts or mods before blaming the base game.

Error: 0x004DD5A3
File: BANKSLOT.DAT
Problem: Project Eagle is not installed on top of GTA San Andreas 1.0. This is not an audio problem, despite the file name - BANKSLOT.DAT lives in the AUDIO folder, but what it means is that the game underneath the mod is the wrong version or is incomplete.
Solution: Check which version you have first - the size of your gta_sa.exe tells you. About 13.7 MB is 1.0 and is correct. About 5 MB is a later version and will not run. About 80 MB is the Definitive Edition, which is a different engine entirely and can never run this mod. If yours is not 1.0, downgrade it: use https://github.com/xxanqw/gtasa-open-downgrader, and do not let it install any "Essential Modifications", because Project Eagle ships those already and duplicates cause their own crashes. Then copy the Project Eagle files over the clean game and replace when asked. Unpacking Project Eagle on its own and running it will never work: the mod ships a patched .exe, not the game. You need the whole game, not just the .exe, and it cannot be a repack - repacks alter the base files. Afterwards rename the folder (for example to "Grand Theft Auto Project Eagle") so Steam cannot update it later and break it again.

File: BANKSLOT.DAT
Problem: Project Eagle is not installed on top of GTA San Andreas 1.0, or the game's AUDIO folder is incomplete.
Solution: Install the mod over a clean GTA San Andreas 1.0 (HOODLUM). Repacks and rips usually will not work. If you are certain your game is 1.0 and complete, check that the whole Project Eagle folder is not set to Read-Only.

Library: discord-rpc.asi
Problem: Discord Rich Presence. The mod is trying to tell Discord what you are playing, and that is what crashed.
Solution: Delete or rename two files - discord-rpc.asi in the game folder, and rich_presence.cs in the cleo folder. Renaming works as well as deleting: add a letter on the end, so .asid and .csd. You will see a harmless error the next time the game starts. You can instead move both into a folder under modloader and switch it off in the main menu under Options, Modloader, Manage Mods.

File: discord-ipc
Problem: Discord Rich Presence. The crash is on the pipe the game uses to talk to Discord.
Solution: Delete or rename discord-rpc.asi in the game folder and rich_presence.cs in the cleo folder. Adding a letter to the extension is enough. This has fixed it for everyone in #bugs-problems who has hit it.

Module: discord-rpc.asi
Problem: Discord Rich Presence crashed inside its own code. The crash address is different every time you run the game, because the plugin is loaded at a different place in memory each launch - so do not go looking up this address, it means nothing on its own.
Solution: Delete or rename discord-rpc.asi in the game folder and rich_presence.cs in the cleo folder.

Error: 0x005B8D47, 0x005B8CA7, 0x005B8CDB
Problem: Project Eagle failed during streaming initialization. This is the largest repeatable startup-crash family in the verified PE logs. QuickTime.qts is often the last library listed, but that is normal startup ordering and is not proof of a codec fault.
Solution: Let every gta_pe.exe, gta_sa.exe, gta-sa.exe and ssmp_launcher.exe process finish before launching again, then start Project Eagle only once. Turn off Windows compatibility mode on all four executables. This family does not yet have a verified universal fix, so if it repeats, post the complete log rather than installing random codec packs or replacing files.

Error: 0xFFFFFFFF
Problem: The game jumped through an invalid pointer while entering the world. In the repeated Project Eagle reports, this forms a world-entry or spawn loop tied to the character's saved position or mission state, not a graphics-driver crash.
Solution: Try an earlier save or a different character if one is available. If the same character crashes at the same point every time, ask Project Eagle staff to move or reset that character's saved position or mission state. Preserve and post the log because a server-side state can reproduce this after every local reinstall.

Module: SA.Audio.cleo+0x82FE
Problem: Extended Radio crashed inside SA.Audio while selecting or changing a station.
Solution: Install or update Valkyrie Crashfix from https://sp-rp.com/#valkyrie-crashfix and keep only one active copy. Check Valkyrie Crashfix.log to confirm its RadioEx hooks installed; merely having an ASI file does not prove this. If the fault still occurs, preserve the new Doctor report. Temporarily disabling RadioEx in every active SA.Audio configuration is an optional troubleshooting step, not a required part of installing Crashfix.

Module: std.data.dll+0xCF7CD, std.data.dll+0xCF7D4, std.data.dll+0x16F7CF, std.data.dll+0x16F6DD, std.data.dll+0xF7CD, std.data.dll+0xF7D4, std.data.dll+0xF6DD, std.data.dll+0xF7CF
Problem: Project Eagle's shutdown reporter faulted after the game was already closing. This is a cosmetic exit crash, not the reason for an earlier gameplay failure.
Solution: If this appeared only after you intentionally quit, no repair is needed. If gameplay crashed first, use the earlier log from that launch; the shutdown report describes the reporter's cleanup, not the original failure.

Error: 0x00534134, 0x005B52C2
File: .ipl
Problem: The game crashed while loading Project Eagle map geometry from an IPL placement file.
Solution: Keep the last-file line and post the complete log so the exact map sector can be identified. Restore the named IPL from the Project Eagle archive if you edited or replaced it. There is not yet a verified blanket fix for unmodified installs.

Library: AMDXN32.DLL, atiumdag.dll, igdumdim32.dll, igd12um32xel.dll, igd10iumd32.dll, nvoglv32.dll, nvspcap.dll, d3d9on12.dll
Problem: Your graphics driver crashed while drawing. San Andreas is a 32-bit Direct3D 9 game, and on current hardware - Intel Iris Xe, UHD and Arc especially - it runs through a translation layer where an out-of-date driver faults.
Solution: Update your graphics driver directly from AMD, Intel or NVIDIA rather than through Windows Update. This is the confirmed fix for the Intel case. If the crash address in this log looks like nonsense (something like 0x6C65746E, which is the letters "ntel"), that is the same problem: the driver has corrupted where the game was executing.

Library: bass.dll
Problem: Audio streaming crashed. This can still happen when the Radio Patch is already installed: that patch restores radio content, but it cannot prevent every bad, mismatched, or unsupported sound request.
Solution: Keep the Radio Patch installed. For a radio crash, verify the original AUDIO\STREAMS files and install or update Valkyrie Crashfix from https://sp-rp.com/#valkyrie-crashfix, keeping one active copy. Valkyrie Crashfix covers the verified RadioEx path and guarded 0x0040FB80 crash; other sound-bank failures may have a different cause. Original RadioEx fix discovery and v1 by konradzimorski. Post the complete report with what you were doing.

File: audio/sfx/genrl, audio/sfx/spc_ga, audio/sfx/pain_a, AMBIENCE, BEATS
Problem: Audio streaming. The game crashed loading a sound effect bank. This is the largest unsolved crash group in Project Eagle 1.3.
Solution: Keep the Radio Patch installed and install valkyrie-crashfix.asi if it is absent, but note that a different non-radio sound-bank problem may remain. Check that Project Eagle was installed over a complete GTA SA 1.0 AUDIO folder. If it continues, post the complete report and say what sound or action immediately preceded it.

File: gtasa_vehicleAudioSettings.cfg
Problem: The game is looking for the audio settings of a vehicle model that does not exist. The file is present - it is the car it refers to that is missing.
Solution: Replace gtasa_vehicleAudioSettings.cfg with a corrected copy - a fixed one was posted in #bugs-problems and resolved this outright. Do not edit vehicles.ide or vehicles.img by hand to fix it.

Code: 0xC0000094
File: AUDIO\STREAMS
Problem: Division by zero while playing a radio station. Your original San Andreas radio files were cut, re-compressed or replaced, so the game computed a track length of zero.
Solution: Restore the original AUDIO\STREAMS files from a clean GTA SA 1.0, then install the Radio Patch over the top. If the station logo on screen does not match what you are hearing, open audio settings and scroll to the station actually playing to resynchronise - that mismatch is the warning sign for this crash.

File: AUDIO\STREAMS
Problem: The game crashed while reading a radio station stream. This can happen even with the Radio Patch installed when the underlying AUDIO\STREAMS files are incomplete, altered, or out of sync.
Solution: Keep the Radio Patch installed and install valkyrie-crashfix.asi if it is absent. If both are already present, verify AUDIO\STREAMS against a clean GTA SA 1.0 copy instead of reinstalling the patches blindly. If the station logo does not match what you hear, open audio settings and scroll to the station actually playing to resynchronise.

File: User Tracks
Problem: User Tracks. The game crashed reading one of your own music files.
Solution: User Tracks are not officially supported in Project Eagle 1.3. A patched PECore.asi that adds support was posted in #bugs-problems. Note your music must go in Documents\Project Eagle User Files\User Tracks - the mod also creates a folder called "GTA PE User Files", and music placed in that one is silently ignored. If a particular track crashes it, re-encode it as a plain MP3.

File: MODELS\PLAYER.IMG, skin.img
Problem: A player skin. This crash is not solved yet - it happens when selecting a skin, including through RZL trainer's own selector, and it has been reported with skin.img correctly added to gta.dat and rebuilt.
Solution: There is no known fix. Avoid the skin selector for now. If you can reproduce it reliably, please post this log and say exactly which skin you picked - this one needs a reproduction case more than it needs another report.

Library: version.dll
Problem: A plugin failed while loading. version.dll is the ASI loader, so it being the last library loaded means the game died while starting up somebody's .asi rather than in the game itself.
Solution: Work through the startup checklist. Install the DirectX and Visual C++ redistributables the mod ships in its extensions download. On Windows 10 and 11, enable DirectPlay, which is off by default and which the game needs: Control Panel, Turn Windows features on or off, Legacy Components, DirectPlay. Add the game folder to your antivirus exceptions, and to Controlled Folder Access if you have ransomware protection on: Windows Security, Virus and threat protection, Ransomware protection, Allow an app through Controlled folder access. Then check the whole game folder does not have the Read-Only attribute set, including subfolders.

Library: gdi32.dll
Problem: Windows display code. The game crashed drawing rather than doing anything game-related, which usually means the display configuration is wrong rather than that a mod is broken.
Solution: Set DPI scaling on the .exe you actually launch - Properties, Compatibility, Change high DPI settings, "Override high DPI scaling behavior", Application - and make sure no compatibility mode is ticked. If your machine has both an integrated and a dedicated GPU, force the game onto the dedicated one through Windows Graphics Settings, the NVIDIA Control Panel or AMD Software; the game sometimes picks the integrated GPU on its own and struggles. Update your graphics driver from the vendor while you are there.

File: .img
Problem: An archive file failed to open. The usual cause is not corruption: the file is still open in another program.
Solution: Close any IMG editor or modding tool that has one of the game's .img files open, then start the game again. If nothing has it open, check the whole game folder is not set to Read-Only and that your antivirus is not holding the file.

File: GTASAsf, User Files
Problem: A save game. Loading or writing your save crashed.
Solution: Saves made in the original GTA San Andreas do not work in Project Eagle - start a new game instead. Not every safehouse in Project Eagle is safe to save at, and there is no published list of which are, so if a particular save crashes reliably, load an earlier one and avoid saving at that location. Also check that Documents\Project Eagle User Files is not Read-Only and is not blocked by Controlled Folder Access or your antivirus, which silently breaks saving.

Library: DINPUT8.dll
Problem: Controller input, almost certainly GInput. This one has no known root cause and GInput has never worked at all for some players.
Solution: Try these in order. First reset your settings by deleting the .set files in Documents under "Project Eagle User Files". Second, open PECore.ini and change TransparentMenu from true to false, which has helped several people. Third, remove GInput and play on keyboard to confirm it is the cause.

File: mousensxy.cs
Problem: The CLEO script mousensxy.cs is not compatible with CLEO 5. It writes machine code into a CLEO buffer and jumps into it, which CLEO 4 allowed and CLEO 5 does not, so the jump lands on memory that is not executable. Note the exception is an execute violation at the script's own address, not a bad pointer.
Solution: Delete mousensxy.cs from the cleo folder. The game will crash the instant the loading screen ends until you do. _noDEP.asi does not help here, because this is page protection on one allocation rather than DEP on the whole process.

Library: CLEO+.cleo
File: CLEO+.cleo
Problem: CLEO+ is not supported by Project Eagle 1.3.
Solution: Delete CLEO+.cleo from the cleo folder. Support was said to be coming in a later update, so check the release notes before adding it back.

File: fastman92limitAdjuster_GTASA.ini
Problem: The limit adjuster. Project Eagle already includes fastman92 Limit Adjuster and configures it - a second copy, or your own edited settings, will fight the bundled one. If you also saw a popup saying "Weapon type ID must be less than...", that is the same cause: you installed the adjuster over the one that came with the mod and overwrote its settings.
Solution: Put the fastman92limitAdjuster_GTASA.ini from the Project Eagle archive back into the game root, replacing the one that is there. Do not install fastman92 Limit Adjuster yourself, do not install any other limit adjuster alongside it, and remove SAEnexLimit.asi from the scripts folder if you added it - the bundled adjuster already covers it.

Library: GTASA.WidescreenFix.asi

Library: debugmenu
